# Pitch Doc

Package this session's artifacts into one demo-first doc built for a
30-second skim, not for documentation completeness.

## Steps

1. **Gather what already exists**: the prototype (mockup file, screenshot,
   or link), the spec/plan doc, and `implementation-notes.md` if present.
   Don't re-derive content that's already written — pull from it.

2. **Lead with the demo.** Put a screenshot, GIF, or link to the prototype
   above the fold, before any prose — this is what gets attention in a
   Slack thread.

3. **Follow with a short what-and-why**: the problem, the approach, the key
   tradeoffs — pulled from the plan doc, not re-argued from scratch.

4. **Keep it skimmable**: short paragraphs, bullets over prose, no wall of
   text. This doc's job is to get buy-in fast, not to be exhaustive.

5. **Skip anything that doesn't serve the pitch** — deep implementation
   detail belongs in the notes file, not here; link to it instead of
   inlining it.
